## 2. 決まっている仕様

### 操作
- 移動 ←→ / A D、ジャンプ Space / Z / W / ↑（長押しで高く。ばねも長押しで高く跳ぶ）、剣 X / J / K（ステージ5から）
- ポーズ P / Esc、または画面右上の ⏸。ポーズ画面に操作の一覧が出る。アプリを切り替えると自動でポーズ
- スマホ：横向きの全画面で、操作をゲーム画面に重ねる。移動はスティック：中心は左下の輪（左 90px・下 90px）で動かない。画面の左 45% のどこを押してもよく、輪の中心より 12px 以上右（左）なら右（左）へ動く。押している間は指の位置の丸が輪の中で左右に動く（2026-11-03 に、押した所が中心になる形から変えた）。ジャンプ・剣は右のボタン。何本の指でも同時に効く。全画面にするボタンはポーズ画面の中（iPhone の Safari は全画面の機能が無いので、代わりにホーム画面に追加の案内を開く）
- ホーム画面に追加の案内：スマホのブラウザで開いたとき、タイトル画面と「横向きにしてください」の画面にボタンを出す。iPhone・Android のタブで、手順を画面の絵（イメージ）で見せる。ホームのアイコンから開いたときは出さない

### ユニット（ギミックの単位）
- 面は、意味を持たせた「ユニット」を並べて作る。並びとデザインの意図は `stages/stageNN.csv` に書き、地形はコード（`STAGE_UNITS`）に書く。両方の並び（番号・種類・部品）が一致しているかは `tests/units.js` で確かめる。ユニットを足す・入れ替えるときは、CSV とコードを両方直す。
- CSV の列：`ステージ, 番号, 種類（スタート／ユニット／中間／ボス前／ボス／クリア）, 部品（コードの U の名前）, 形（部品のどの形か）, ギミック, 役割, 失敗の損失, 意図, 道, 向き, 似ないための工夫`。
  - 役割：教える → 試す → 組み合わせ → ひねり。ほかに 選ぶ（分かれ道）・休む（中間）・確かめる（ボス）・ごほうび（クリア）。
  - 失敗の損失は段階的に重くする：教える＝時間（`back`：段を上がった道から落ちると、下の通路を左へ歩いて戻り、段を上り直す。約3秒。`tests/back.js`）→ 試す＝ダメージ（落ちると HP-2）。上下の床（1-8）・ばね付きの動く床（7-2）は下を床にして損失を時間にした。
  - 道：本道／分かれ道（本道／寄り道＝遠回りでハート）／分かれ道（倒す／避ける＝撃つ敵を上の段で先に倒すか、下の道を撃たれながら走り抜けるか）。どちらを選んでもゴールに着く。
  - 向き：横／上へ（縦に登る・ばね・上下に動く床）／下へ（段を下りる）／折り返し（右へ進んで行き止まり、上の通路を左へ戻り、さらに上へ）／折り返し（下へ）（`switchDown`：上の通路の右端の穴から中の通路へ、左端の穴から下の通路へ）。
  - 似ないための工夫：同じ部品でも面ごとに形を変える（撃つ敵の段・寄り道・縦の登り・折り返し）。一覧は `docs/design/variants.csv`。撃つ敵の段の「身を隠す壁つき」（5-6・9-7）は、撃つ敵が下の道の低い台の上にいて、近づき方を選ぶ（分かれ道はない。上の台に置くと穴を跳ぶときに頭を打つため）。
- 中間地点は CSV の「中間」の行の場所にある（スタートとボス前も中間地点）。画面の上には、いまいるユニットの番号（CSV の番号と同じ）が出る。
- 崩れる床は「安全な地面」にならない（落ちたあと戻る場所にならない）。崩れる階段（`tileStairs`）で下りる高さの合計が 460px を超えると、下に着いたときに落ちた扱いで上へ戻されるので、2-8・8-8 は約 370px にしている。
- 中間セーブには地形の版（`LAYOUT`）を残し、版が違う中間セーブは使わない（作り直す前の中間セーブは消える）。

- 中間地点のまわりには敵を置かない。
  - 中間地点の前後150pxに立っていて、敵が250px以内に来ず、弾も届かないようにする。地形を作ったあと、届く範囲（撃つ敵は560px、ハチは260pxで突っ込む、イノシシは見回りの外へ120px走る、ほかは見回りの範囲）がそこに掛かる敵を外す（`loadStage` の `cpReach`）。これで外れる敵は各面1〜7体。`tests/cpsafe.js` で確かめる。
- ボス部屋の手前にも中間地点がある（ボスにやられたら、そこから）。手前の床は敵の無い 1100px で、中間地点はその 650px 目（ボス部屋の 450px 手前）。撃つ敵の届く 560px より遠くなるようにしている。
- ステージ2の20回（3・4面の10回より難しい）は、指定どおりにしている。

### プレイヤー
- 道中のHPは上の表のとおり。ダメージは敵によって1〜3。ハートで3回復。
- EASY モード：ステージ選択の右上のボタン（キーボードは E）で切り替える。ON のとき、プレイヤーの HP とハートの回復量が10倍（ボス部屋の気合いは、その3倍）。ボスと敵は変わらない。次に面を始めたときから効き、設定は端末（`progress.easy`）に残る。画面上に「EASY」と出る。EASY のクリアも次の面を開くのに数えるが、「★ 最少○回」は更新しない。
- 落ちても即死ではなく、HPが2減って直前の地面に戻る。HPが0になったら、セーブ地点からやり直す。
- 1〜4面は剣が無い（ボタンも出ない）。1〜4面の敵は、1回踏めば倒れる。
- トゲの敵は、踏むと自分がダメージを受ける（剣で倒す）。それ以外の敵は、足が上側35%にあれば、上昇中でも踏んだことになる。

### ボス戦
- 部屋に入ると、プレイヤーが気合いを入れ、最大HPが3倍になって全回復する（約1.2秒、その間は時間が止まる）。やられたら、道中のHPに戻る。
- 体力が半分（切り上げ）になると第2形態になる。ほえて約1.2秒無敵になり、赤いオーラをまとい、新しい技が増える。
- **予備動作 → 避ける → 攻撃** のくり返し。避けたあとの隙では2ダメージ。攻撃が体に当たったとき（無敵時間中も含む）は、隙ができない。
  - **B 型**：避けたあとの隙だけダメージが入る。
  - **A 型**：ふだんも当てれば1ダメージ（ただし当てにくい）。
- 目を回すボスは、うずまきの目と、頭の上で回る★を出す。ロボは機械なので★を出さず、コアが開いて湯気が出る。
- トゲのあるボス（騎士の兜、魔王の角）は、踏めるとき（目を回したとき）だけトゲが消える。それ以外のときに踏むと、自分がダメージを受ける。
- ダメージを与えると、プレイヤーは反動で後ろへ戻り、ボスは約0.7秒無敵になる（続けて踏めない）。
- ボス戦の長さの目標は、約2分。

| ボス | 予備動作 → 攻撃 | 避けたあとの隙 |
|---|---|---|
| イノシシ | 土をかく → 突進（第2形態：壁で折り返してもう一度、跳んで衝撃波） | 壁に当たって目を回す |
| 天井グモ | 震えて床の影が大きくなる → 落ちてくる（第2形態：2回続けて、糸を3方向） | 脚が床に刺さる |
| 雪だるま | しゃがんで足もとが光る → すべって突進。腕を上げる → 雪玉 | 壁に当たって目を回す（ふだんは頭を踏んで1） |
| ロボアーム | 天井のアームが拳を振り上げてプレイヤーの真上へ（床に影）→ 振り下ろす。コアが赤く光る → レーザー（低い・高い。台と床で避ける。コアの横の小さな足場なら当たらない） | 拳が床に刺さる（湯気 1.5 秒）：踏むと1。乗ったままでいると腕が戻るときにコアの横まで運ばれ、開いたコアを踏むと2。レーザーを撃ち終わってもコアが開く（右のばね・コアの横の足場から踏む）。第2形態はアームが2本で、刺さった拳を乗り継げる。当てると火花とネジ、体力が減るほど装甲がはがれて煙が増える。設計は `docs/design/boss_robo.csv` |
| 盾の騎士 | 槍を引いて光る → 突き（第2形態：2連続、槍投げ） | よろける（ふだんは背中を剣で斬って1） |
| 氷のコウモリ | 翼をたたみ、目が赤く光り、狙う線 → 急降下。つららは影で予告 | 氷の床に刺さる |
| 風の鳥 | 止まって地面に影 → 急降下。翼を広げる → 突風と羽 | くちばしが刺さる |
| 溶岩トカゲ | 泡 → 飛びかかる。口が光る → 火の玉 | 着地でふらつく（岸にいる間は1） |
| 雷の竜 | 赤い柱 → 雷。口が光る → 炎。頭が光って端へ → 低く体当たり | 壁にぶつかる |
| 魔王 | 第1：角が光る → 突進。第2：真上に影 → 落ちてくる、輪が光る → 弾の輪 | 目を回して角が引っこむ |

### クリアの流れと宝
- とどめで 0.5 秒止まって白く光る → ボスが揺れてかけらになって消える → 宝が出て跳ね、床（台の下ではない所）に落ちる → 自分で取りに行く（取るまで時間は止まる）→ 頭の上に掲げる（1 秒、光の輪）→ 画面の上へ飛ぶ → クリアの画面（宝の欄 10 枠）。流れは `docs/design/clear.csv`。
- 宝は `docs/design/rewards.csv`：1〜3・5〜9面は色違いの鍵のかけら（8つ）、4面は剣（5面から剣が使える理由）、10面は王冠。取った宝は端末（`progress.items`）に残り、ステージ選択の枠に絵が出る。宝の名前は文字で出さない（絵だけ）。
- 10面のスタートの先に城の扉があり、近づくと鍵のかけらが鍵穴に集まって扉が上がる。
- `tests/reward.js` で、全10面で宝を歩いて取れてクリアの画面になり、記録されるか、10面の扉が開くかを確かめる。

### 表示の方針
- 操作以外の説明は、文章で出さない（エフェクトや動きで伝える）。出す文字は、ステージ名、ボス名、操作の説明だけ。
- 例外：ホーム画面に追加の案内は、ゲームの外のメタ的な説明書なので、文章と絵で出してよい（2026-11-02 に決めた）。
- 4面の宝（剣）のクリアの画面だけは、文字ではなく宝の欄の絵で示す（宝の名前も文字で出さない）。

### 見た目のテーマ：切り絵と和紙（2026-11-03 に決めた。候補と比べたページは docs/design/art/）
- どの形も、縁を揺らして切った染め紙を重ね、薄い影と和紙の目を付ける（`paper()`）。光る円は使わず、明るい紙を輪に切って重ねる（`glow()`・`ring()`。予備動作の合図もこれ）。
- 文字は明朝体（`fnt()`・`inkText()`）。絵文字は使わない（ボタンの絵は線の絵、ポーズは「中断」の札）。
- 色は面ごとの染め紙（`STAGES[].theme`）。プレイヤー（マフラーの紙人形）と敵はどの面でも同じ色で、暗い面だけ縁を明るくする（`rim`）。
- 速さのため、背景（空・遠景・中景）、地形の上の面、プレイヤー・敵・宝は、面を読み込んだときに1回だけ描いて使い回す（`buildArt()`・`spr()`）。毎フレーム描くボスと弾は、部品ごとの種で縁の揺れを決め（ちらつかない）、影をぼかさない（`lp()`）。Mac の Chrome で、道中1フレーム約 0.2 ms、ロボアーム戦 約 1 ms、面の絵を作るのは面の最初に 30〜70 ms。
- テスト（Node）では絵を描かない（`tests/gh.js` の `NO_ART`）。

### 進み具合の記録・デバッグモード
- クリアした面は、端末（localStorage の `sidescroll10_progress`）に保存する。クリアした面の次まで選べる。
- 中間セーブも同じ場所（`progress.resume`）に1つだけ残す。中間地点を通ったとき・やられたとき・ポーズ（アプリの切り替えを含む）のときに、面・中間地点・挑戦回数・時間を書く。その面を選ぶと中間地点から続き、挑戦回数と時間も引き継ぐ。ステージ選択では、中間セーブのある面に小さな緑の旗を出す。
- 中間セーブは、その面をクリアしたときと「やり直し」（R キー）で消える。別の面で中間地点を通ると上書きされる。
- **デバッグモード**：タイトルかステージ選択の画面で、**左上と右上の角を交互に合わせて5回**タップする。
  - 全部の面が選べる
  - 始める地点を、最初・各中間・ボスから選べる
  - ポーズ画面で無敵を切り替えられる
  - デバッグ中のクリアは記録しない

## 3. コードの作り（`index.html` の `<script>` の中）

| 部分 | 中身 |
|---|---|
| `STAGES` | 面ごとの定義（名前、ギミック、ボス、体力、色） |
| `U` | ユニットの部品（`dent`・`pits`・`climb`・`switchback`・`detour`・`snipe`・`movers`・`crumble` など）。値を受け取って地形・敵・ハートを置き、道筋の足場を `route`（寄り道は `alts`）に記録する |
| `STAGE_UNITS` ＋ `buildUnits()` | 面ごとのユニットの並び（`[番号, 種類, 部品, 値]`）。`stages/stageNN.csv` と同じ並び。乱数は使わない。10面は城の扉（`castleDoor`）も置く |
| `updateReward()` / `updateGot()` / `drawItem()` / `updateDoor()` | クリアの流れ（宝が落ちる・取る・掲げる・飛ぶ）、宝の絵、10面の扉 |
| `ARENA_BUILD` | ボス部屋の地形（ボスごと） |
| `updatePlayer()` | 移動、すべる床、ばね、崩れる床、剣、落下からの戻り、中間地点 |
| `updateEnemies()` / `updateShots()` | 敵（walk / hop / shoot / bee / boar / spike）と弾（seed / wave / rock / beam / bolt） |
| `BOSS.robo` の `fists` | ロボアームの拳。動く床（`movers`）に `custom` として入れ、ボスが動かす（刺さっている・戻る間だけ乗れる）。拳を踏んだダメージは `B.extDamage` で共通の処理へ（反動なし） |
| `BOSS` | ボスごとに `init / start / update / dizzy / hurtBy / contact / onHit / draw`、トゲのあるボスは `spikyNow` |
| `updateBoss()` | ボスに共通の処理（ダメージ、反動、無敵、第2形態への切り替え、踏み判定、攻撃が当たったか `connected`） |
| `paper()`・`spr()`・`buildArt()` ほか（「紙の絵」の章） | 切り絵と和紙の描き方。背景・地形・プレイヤー・敵・宝・ボス（`BOSS_ART`）・画面上の欄・メニュー |
| `screenButtons()` / `handleScreenTap()` | メニューのボタン、ポーズ、デバッグモードの角のタップ |

調整するときによく触る値：
- `MAX_HP_BY_STAGE`
- `STAGES[].bossHp`
- 各ボスの `B.timer` の秒数（予備動作や隙の長さ）
- `hurtBy` の戻り値（ダメージ）

## 4. 分かっている問題

1. **人が遊んでの確認は、一度もしていない。** 挑戦回数、各区間の長さ、ボス戦の長さ、予備動作の読みやすさは、どれも確かめていない。
2. 自動テストでは、ボス戦が目標の約2分より短く出た。攻撃を必ず避ける前提で、隙のときだけ攻撃すると19〜64秒。クモ（19秒）とイノシシ（24秒）は特に短い。
3. A 型の雪だるま・鳥・竜は、ふだんの1ダメージを当て続けると10〜20秒で倒せた（テストではプレイヤーを瞬間移動させている）。人が遊んで早すぎるなら、当てにくくする必要がある。
4. ユニットで作り直した面（2026-11-03）は、道筋の自動プレイ（`tests/route.js`）で全10面の本道と分かれ道をボス部屋まで通れる。人が遊んでの難しさ・長さ・読みやすさは確かめていない。
5. 作り直した面の敵は各面 3〜10 体で、作り直す前（19〜152 体）よりずっと少ない。ユニットの意図に要る敵だけを置いた。にぎやかさが足りなければ、ユニットの値（`en`）で足す。
8. 作り直したロボアームの手触り（拳の速さ・隙の長さ・運ばれる高さ）と、クリアの演出の長さは、人が遊んで確かめていない。
6. iPhone の Safari では、横向きの固定と全画面が効かない（そのときは「横向きにしてください」と出る）。ホーム画面に追加して開くのが代わりの手（案内あり）。案内の絵は実機の画面を写したものではなく、実機ではまだ確かめていない。
7. スマホの実機では、一度も試していない。

## 5. 次にやること（おすすめの順）

1. デバッグモードで、各ボスと戦う（スマホとPCの両方）。予備動作が読めるか、約2分になるか、を確かめる。
2. その結果を見て、ボスの体力・予備動作の長さ・A 型の当てやすさを調整する（3章の値）。
3. 1面から順に人が遊んで、ユニットごとの難しさと長さを確かめる。直すときは `STAGE_UNITS` の値と、CSV の意図を両方直す（`tests/units.js`）。
4. 版の管理と共有：Git のリポジトリと GitHub Pages に移した（README）。

## 6. テストの走らせ方（`tests/`）

ブラウザを使わず、Node 上で描画を空にしてゲームを動かします。先に、HTML からスクリプトを取り出します。

```sh
cd tests
sh extract.sh ../index.html        # → tests/g.js を作る（node --check もする）
node gh.js info                    # 全10面の地形（部品の数、セーブ地点、敵の数、ボス部屋の位置）
node gh.js boss                    # ボス部屋から自動で戦う（無敵、各3分）
node gh.js run                     # 1面目から単純な自動プレイ（無敵、各10分）。エラーと、どこまで進んだか
node route.js                      # 道筋の自動プレイ：ユニットが記録した足場を本物の物理で辿り、全10面でボス部屋まで行けるか（越えられなければ終了コード1）
node route.js alt                  # 同じく、寄り道・撃つ敵の段も全部通る
node units.js                      # stages/*.csv とコードのユニットの並びが一致するか（違えば終了コード1）
node back.js                       # 落ちると戻される（back）：下の通路に落ちてもダメージなしで、段から上り直せるか（かかる時間も出す）
node reward.js                     # クリアの流れ：全10面で宝を歩いて取れて、クリアの画面になり、記録されるか。10面の扉が開くか
node t4.js dizzy                   # 攻撃を必ず避ける前提で、隙のときだけ攻撃した戦闘時間
node t4.js any                     # 同じ前提で、当てられるときはいつでも攻撃した戦闘時間
node t5.js                         # 立ち止まって攻撃を受け続けたとき、隙ができないか
node gap.js                        # 越えられない穴（130px超で、動く床もばねも無い）が無いか
node ui.js                         # デバッグモードの角のタップと、ステージ選択
node k.js                          # ボス部屋での気合い（最大HP×3）と、やられたあとのHP
node save.js                       # 中間セーブが再読み込みのあとも残るか、やり直し・クリアで消えるか
node cpsafe.js                     # 全部の中間地点（スタート・ボス前を含む）の前後で、ダメージ・250px以内の弾・敵が無いか（あれば終了コード1）
node bosscp.js                     # ボス前の中間地点：まわりに敵がいないか、歩いて入れるか、やられたらそこへ戻るか
node easy.js                       # EASY モード：HP とハートの10倍、ボス部屋、最少回数を更新しない、再読み込みのあとも残るか
node robo.js                       # ロボアーム戦：レーザーを避けられる押し始めの幅、ばねからコアを踏めるか、拳を踏めるか、拳に運ばれてコアを踏めるか
```

- 自動プレイは単純な操作なので、人の難しさの目安にはならない。主な役目は、エラーと矛盾を見つけること。
- どれも数十秒〜2分ほどで終わる。メモリはわずか。
